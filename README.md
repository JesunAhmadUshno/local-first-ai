# local-first-ai

**Question.** Can a fully offline, standard-library assistant answer
questions over private documents with cited answers and correct
refusals, and how does it compare with hosted models on cost, speed,
quality and privacy?

**Headline.** Exploratory, not pre-registered: on a synthetic 24-document corpus the offline TF-IDF core found the right document for 20 of 20 evidence questions (Wilson 95% interval 0.839 to 1.000) and refused 4 of 4 no-evidence questions under a leave-one-out threshold (interval 0.510 to 1.000), but on a 16-question hard set it answered only 2 of 10 paraphrases correctly and refused only 2 of 6 distractors; no language model ran, and the cloud side is modelled from published pricing, not measured.

**Field.** ML and AI research. **Job family.** Applied ML and AI
engineering (private, on-device retrieval and assistants).

**Verdict.** Functional, not pre-registered. The local pipeline has
run end to end on its corpus, its recorded results regenerate from the
committed code and corpus (wall clock fields aside), and tests pass in
CI on Python 3.11 and 3.12. No plan with pass lines was committed
before the results, so the verdict is capped at Functional until the
confirmatory re-run drafted in PROPOSAL.md is locked and run.

Live dashboard: https://jesunahmadushno.github.io/local-first-ai/ (the
Build pipeline running in your browser; the build fails unless the
browser port reproduces every recorded result).

## Reproduce

```text
python3 src/check_results.py
python3 -m unittest discover -s tests -p "test_*.py" -v
cd site && npm ci && npm run build
```

Python 3 standard library only; Node 22 for the dashboard. The first
command re-runs src/run_learn.py, src/run_build.py, src/run_deep.py and
src/run_rigor.py and fails if any file in results/ changes, apart from
the wall clock fields. REPORT.md ("Headline evidence") lists the
command that prints each headline number.
